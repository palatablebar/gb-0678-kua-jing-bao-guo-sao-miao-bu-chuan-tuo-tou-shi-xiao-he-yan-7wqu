# 扫描时效定义

scan_id是扫描事件唯一键，parcel是包裹号。节点按收件、起运、清关、妥投顺序推进；可缺中间节点，但必须有收件。按event_time排序，received_time仅用于上传延迟。倒退扫描隔离，不改写先前妥投事件。妥投使用最早有效发生时刻。

目的地JP/US/DE对应东京/纽约/柏林。正式时效采用合同口径（DESTINATION_WORKING_CALENDAR）：承诺时钟仅按目的地当地工作日小时计时，目的地周末与法定节假日停表；起运地及海外作业地的周末、节假日与当地停工均不属于合同免责，一律不扣除、计入承诺时长，承运商主张的“海外作业地周末扣除”不予采纳。时效以目的地工作日小时计算，周末与节假日停表。JP含2026-11-03与11-23，US含11-26，DE含10-03；支持按参数覆盖假日。M5逐包裹输出clock_segments（按目的地当地自然日半开切段，标注working/weekend/holiday、计入与停表小时及逐条依据）与clock_basis口径说明；逐段计入小时之和等于working_hours，不一致即CLOCK_MISMATCH拒绝。未妥投计算至as_of，默认2026-11-18T00:00Z。每超时小时赔付1元，上限保价10%，reported为原申报赔付。赔付（M6）与证据下载（/api/runs/<id>/archive）与M5同源，金额以封存批次为准；重试同一补传复用同一run_id，不新增计赔；切换/导入失败不落库，保留上一可用结论。原始扫描单元格_raw与来源行_sources全链路透传，归档缺失原始证据返回RAW_EVIDENCE_LOST。

业务ID和超大整数按文本保形；Decimal参与数量金额计算，对外序列化为字符串。哨兵集合定义在app/values.py，缺失值不能当零。所有时间带UTC偏移，先转UTC比较，业务日按指定地区划分。区间统一[start,end)。重复业务键保留第一条、完全相同行计重复；值冲突行隔离且保留原值。空文件、全空白、仅表头分开拒绝。

运行清单包括输入sha256、规则版本、参数、生成时刻与耗时。源行编号以CSV解析器的物理结束行号表示，引号内换行不增加记录数。输入超过4MB返回413，非法表头和类型返回422，失效版本复核返回409。
